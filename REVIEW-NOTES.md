## Browser tooling notes

**When the Browser pane is not displayed, `document.hidden` is `true` and Chromium suspends the compositor entirely** — `requestAnimationFrame` doesn't fire, `IntersectionObserver` callbacks don't run. Animation and any observer-driven behaviour (native marquee's own JS included — see `ARCHITECTURE.md` §50) cannot be measured in that state, full stop, no amount of waiting fixes it. A "nothing is animating" or "the JS never ran" observation from a hidden pane is a tooling artefact, not a defect in the page. **Check a foreground tab (`tabs_context`, look for `browserOpen`/the "pane is hidden" note, or read `document.hidden` directly) before debugging** anything that depends on rendering being live — don't conclude the code is broken from a hidden-pane read.
